## 一、setup.bat 体验问题

### 问题
- 双击运行 → 中文乱码（即便 `chcp 65001` 已设置，cmd 默认 GBK 仍可能在
  解释字节流时把脚本本身的中文当成 GBK 解码）
- 失败时静默退出，用户看不到任何错误信息
- 成功时只 `pause` 一下，没明确告诉"`.env.docker` 在哪、下一步做什么"

### 修复
- **全英文输出**：所有 echo 改 ASCII 英文，彻底规避 cmd 代码页问题；
  脚本头注释里指明全文档以 INSTALL.md 为主
- **每步 OK/ERROR 显式打印**：PowerShell 调用、文件写入、空输入都
  独立检查；任何失败都打印原因 + `pause` + `exit /b 1`
- **结束摘要**：打印 `.env.docker` 的绝对路径 + 访问 URL +
  下一步 docker compose 命令，最后再 `pause` 让用户看清

### 为什么不直接保留中文
即便用 UTF-8 with BOM 保存 .bat，仍有部分 Windows 用户在
"中文(简体, GBK)" 系统区域下双击时遇到首屏闪烁乱码。英文是最稳的
兜底。中文体验在 setup.sh / INSTALL.md 中保留。

## 二、Nginx 冷启 502

### 问题
首次 `docker compose up -d --build`，nginx 容器先于 app 就绪并开始转发
请求，用户访问立刻看到 502 Bad Gateway 或空白页。要等 Next.js 完成
冷启动（~30s）后刷新才正常。

### 修复
docker-compose.yml：
- **app 加 healthcheck**：用 node 自带 http 模块 GET `/api/health`，
  避免在 alpine 镜像里引入 curl/wget
  ```yaml
  test: ["CMD", "node", "-e", "require('http').get('http://127.0.0.1:3000/api/health',r=>process.exit(r.statusCode===200?0:1)).on('error',()=>process.exit(1))"]
  start_period: 30s
  retries: 12
  ```
- **nginx depends_on 改 condition**：`app: condition: service_healthy`，
  app 没 healthy 时 nginx 根本不会启动

`/api/health` 在 V2.x 就已存在，零代码改动。

### 7.3 Windows 本机冒烟测试结果

**测试环境**：Windows 10 + Docker Desktop 4.75（WSL2 后端）

**测试路径**：
1. `git clone https://github.com/zhongzhir/aivestor.git && cd aivestor`
2. 双击 `setup.bat`（生成 .env.docker）
3. `docker compose --env-file .env.docker up -d --build`
4. 注册账号 → 配置 API Key → 上传 BP → 生成报告
5. `docker compose down && docker compose --env-file .env.docker up -d` 验证持久化

**实测发现 1：Windows 80 端口权限拒绝**
```
ports are not available: exposing port TCP 0.0.0.0:80
```
Windows 对 80 端口有权限限制（常见占用源：IIS、World Wide Web Publishing
Service、Hyper-V 端口保留区段）。**解决**：把 nginx 端口映射改 `8080:80`，
同步 `NEXTAUTH_URL=http://localhost:8080`，访问 `http://localhost:8080`。

**实测发现 2：ENCRYPTION_KEY 留空导致 API Key 保存 500**
手动按 .env.docker.example 配置时，用户跳过了 ENCRYPTION_KEY（注释只给了
node 命令，未装 Node 的 Windows 用户无从下手），结果保存 API Key 时
AES-256-GCM 初始化 throw，浏览器看到 500。**解决**：补 PowerShell 原生生成
命令（无依赖），见 7.5。

**最终通过**：注册、API Key 保存、BP 上传、报告生成、`down + up` 后数据
仍在，全部通过。

### 7.5 ENCRYPTION_KEY 生成命令补全 · `e5b9006`

`.env.docker.example` 里 `ENCRYPTION_KEY` 的注释扩成三套命令：

```
# Linux / macOS：
#   openssl rand -hex 32
# 或（需 Node.js）：
#   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# Windows PowerShell（无需额外依赖）：
#   -join ((1..64) | ForEach-Object { "{0:x}" -f (Get-Random -Maximum 16) })
```

本机实测 PS 命令产出 64 位 hex，正则 `^[0-9a-f]{64}$` 校验通过。

> 备注：PS 命令用的是 `Get-Random`（System.Random），对配置密钥这一档
> 够用。`setup.bat` 用的是 `[Security.Cryptography.RandomNumberGenerator]`，
> 加密学安全；example 注释为照顾"手动复制贴的用户"，挑了最短的写法。
> 如果未来想加固，可以把 example 注释也换成 RandomNumberGenerator 版本。
