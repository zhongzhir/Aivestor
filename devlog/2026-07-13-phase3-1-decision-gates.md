# 2026-07-13 Phase 3.1：投资节点控制

## 背景

Phase 3 首版把 IC Memo 放入“决策辅助”标签内。用户反馈该结构功能可用，但会让 IC Memo 更像一个分析工具，而不是投资流程中的正式节点。

本次调整采用“流程节点控制 + 节点内工作区”的双层结构：

- 流程节点控制：记录项目处于哪个正式投资节点，以及该节点的结论。
- 节点内工作区：IC Memo、反方视角、历史镜像、条款草案等能力服务于节点推进。

## 已实现

- 新增迁移 `db/migrations/036_project_decision_events.sql`。
- 新增表 `project_decision_events`，记录项目节点、节点类型、节点结果、标题、备注、操作者、组织归属和时间。
- 新增 API `POST/GET /api/projects/[id]/decision-events`。
- 项目详情页将“决策辅助”改为“投资决策”。
- 在“投资决策”顶部新增“投资节点控制”卡片。
- 节点控制支持手动记录：
  - 流程节点：初筛、尽调、投委会、投后、Pass、退出
  - 节点类型：阶段节点、立项决策、IC Memo、投委会决议、条款决策、投后节点、退出决策
  - 节点结果：草稿、待审议、通过、否决、暂缓、需补充材料、已记录
- 保存节点记录时同步更新项目 `process_stage`。
- 节点记录进入“项目记录”时间线，成为可回看的项目支点。

## 设计边界

- 本阶段不做完整工作流引擎。
- 本阶段不做复杂审批权限和多人签批。
- 本阶段不自动生成 IC Memo 草稿表。
- 本阶段重点是让项目详情页具备“正式节点”的产品骨架。

## 后续建议

1. 给 `project_decision_events` 增加详情页或抽屉，展示完整节点记录。
2. 支持从节点记录生成 IC Memo 草稿或归档版。
3. 组织版增加团队成员判断对比和节点结论确认。
4. 后续投后管理单独设计，不混入 Phase 3 投前决策流程。
