## 关键决策

- **「数据应用」入口的能力位判断**：capabilities 不进 JWT（P1 1.4 决策），Sidebar 是 client 组件无法调 `hasCapability`。故在服务端 `(app)/layout.tsx` 现取 `hasCapability(orgId,'data_apps')`（30s 缓存，仅对有 orgId 的用户查）后以 `dataAppsEnabled` prop 下发 Sidebar。比「组织工作台」纯 session 判断多一层能力位，符合 6.1 要求。
- **injectMarketContext 未直接复用 `knowledgeSearch.searchZjjr`**：该私有函数返回的 `content` 已内联来源标注、且不单独暴露 `data_as_of`，无法满足 8.4 的「头部标注 + 原始 content」格式。故在 orgInject 内单写一个聚焦查询 `searchZjjrFeatures`（同向量口径，返回 title/content/data_as_of），与 `injectOrgKnowledge` 的 `searchOrgKnowledge` 自包含模式一致。
- **动态组件加载**：`[appId]` 页 Server Component 内 `await app.component()` 取模块 default（"use client" 组件）渲染，路径静态可分析、按需分包，避免 next/dynamic 额外封装。

## 验证方式

- **能力位关闭全链路不可达**：`data_apps:false` → Sidebar 无入口、`/data-apps` 与 `/data-apps/[appId]` redirect /dashboard、各 `/api/data-apps/*` 403；`zjjr_data:false` → 点查/洞察 API 403、injectMarketContext 返回原文。
- **injectMarketContext**：① 无 `zjjr_data` → system prompt 与改造前逐字一致；② `zjjr_features` 为空 → 静默（无报错、prompt 不变）；③ smoke-test 跑通后有数据 → 注入 ≤5 条带标注片段 + 防穷举规则。
- **点查频控**：同一用户 1 小时内第 61 次搜索/详情请求 → 429。
- **Fixture smoke-test（ECS）**：`cd services/zjjr-sync && npx ts-node scripts/smoke-test.ts` 后 `zjjr_features` 有数据、机构点查能搜到 Fixture 机构（如「晨曦创投」「云岭资本」）。
