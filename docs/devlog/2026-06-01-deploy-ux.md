## 一、setup.bat 体验问题

### 问题
- 双击运行 → 中文乱码（即便 `chcp 65001` 已设置，cmd 默认 GBK 仍可能在
  解释字节流时把脚本本身的中文当成 GBK 解码）
- 失败时静默退出，用户看不到任何错误信息
- 成功时只 `pause` 一下，没明确告诉"`.env.docker` 在哪、下一步做什么"

### 修复
- **全英文输出**：所有 echo 改 ASCII 英文，彻底规避 cmd 代码页问题；
  脚本头注释里指明全文档以 INSTALL.md 为主
- **每步 OK/ERROR 显式打印**：PowerShell 调用、文件写入、空输入都
  独立检查；任何失败都打印原因 + `pause` + `exit /b 1`
- **结束摘要**：打印 `.env.docker` 的绝对路径 + 访问 URL +
  下一步 docker compose 命令，最后再 `pause` 让用户看清

### 为什么不直接保留中文
即便用 UTF-8 with BOM 保存 .bat，仍有部分 Windows 用户在
"中文(简体, GBK)" 系统区域下双击时遇到首屏闪烁乱码。英文是最稳的
兜底。中文体验在 setup.sh / INSTALL.md 中保留。

## 二、Nginx 冷启 502

### 问题
首次 `docker compose up -d --build`，nginx 容器先于 app 就绪并开始转发
请求，用户访问立刻看到 502 Bad Gateway 或空白页。要等 Next.js 完成
冷启动（~30s）后刷新才正常。

### 修复
docker-compose.yml：
- **app 加 healthcheck**：用 node 自带 http 模块 GET `/api/health`，
  避免在 alpine 镜像里引入 curl/wget
  ```yaml
  test: ["CMD", "node", "-e", "require('http').get('http://127.0.0.1:3000/api/health',r=>process.exit(r.statusCode===200?0:1)).on('error',()=>process.exit(1))"]
  start_period: 30s
  retries: 12
  ```
- **nginx depends_on 改 condition**：`app: condition: service_healthy`，
  app 没 healthy 时 nginx 根本不会启动

`/api/health` 在 V2.x 就已存在，零代码改动。

## 三、发布包与开发文件隔离

### 问题
用户下载 zip 或 tar.gz 后，目录里夹着 `AIVESTOR_CONTEXT.md` / `docs/devlog/` /
`src/` 等开发文件，对部署人员没用，也降低产品观感。

### 修复
- **.dockerignore**：构建镜像时排除开发文档与 .git，缩小镜像层
- **.gitignore**：补 `.env.docker`、`release/`、`aivestor-*.tar.gz`
  防止误提交真实密钥与发布产物
- **scripts/pack-release.sh**：把 `docker-compose.yml`、`docker/`、
  `setup.{sh,bat}`、`INSTALL.md`、`.env.docker.example` 打成
  `release/aivestor-<version>.tar.gz`；同时用 sed 把 compose 文件
  里的 `build:` 段改写成 `image: zhongzhir/aivestor:<version>`，
  让用户从 Docker Hub 拉预构建镜像，不需要本机构建
- **DEPLOYMENT.md**：仓库根目录的一句话指路文件，让从 GitHub 直接
  浏览的人能快速找到 INSTALL.md
