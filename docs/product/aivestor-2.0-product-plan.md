# Aivestor 2.0 产品规划

> 初稿日期：2026-07-10
> 状态更新：2026-07-14
> 范围：股权投资人工作平台的界面方向、2.0 产品需求与阶段实施记录。
> 当前状态：主要实施阶段已完成；本文同时保留最初规划、实施过程中的调整和后续候选项。

> 强制约束：所有 Aivestor 产品开发必须遵循 [`product-development-principles.md`](product-development-principles.md)。产品承担复杂性，默认理解并执行，使用符合常理的默认值，不让用户反复确认、填写程序字段或学习系统内部概念。

## 0. 2.0 落地状态

截至 2026-07-14，2.0 已从规划进入可用产品，主要落地范围包括：

- Investment Desk 视觉基调、投资人工作台、工作流导航与项目管线升级。
- 项目工作区的下一步动作、负责人、截止日期、证据完整度与统一活动时间线。
- 投资节点控制、项目内 IC Memo 生成/编辑/评审，以及正式决策事件留痕。
- 投后材料收集、监控视图、结构化指标、行动项、退出策略和投后报告输出。
- 轻量关系记录与项目内个人/机构知识上下文。
- AI 服务余额错误提示、平台试用额度与自有 API Key 之间的切换体验。

这不代表原规划中的所有长期设想都已完成。完整 CRM、邮件/日历自动捕捉、复杂自定义工作流、跨项目财务比较等仍属于后续范围。

## 1. 执行摘要

Aivestor 1.x 已经具备相当完整的功能深度：项目分析、私有知识库、SKILL 工作流、组织工作台、报告导出、项目档案、投后记录和数据应用。当前的主要问题不是“AI 能力不够”，而是产品体验还更像一组工具页面，而不是投资人每天真正使用的工作系统。

Aivestor 2.0 应该从“AI 报告生成器 + 知识库”升级为“覆盖项目来源、尽调、决策记忆、投后跟踪和对外汇报的投资工作台”。2.0 的体验应该让用户的工作形成连续感：

- 今天有哪些事情需要我处理？
- 哪些项目正在推进、停滞，或者缺少关键证据？
- 我上次看完之后发生了什么变化？
- 我知道什么、团队知道什么、市场数据又说明什么？
- 当时做了什么决策，为什么，由谁做出，后续结果如何？

推荐的 2.0 产品方向：

1. 将首页从简单 Dashboard 升级为“投资人工作台”。
2. 围绕交易生命周期重建项目页，而不是继续堆叠孤立 Tab。
3. 增加轻量关系与上下文捕捉能力，但不要一开始就做重型 CRM。
4. 将知识、报告和判断转化为工作中的可见证据链。
5. 将机构工作流扩展到 IC 准备、投后监控、LP/协会报告等高频场景。
6. 使用更温暖、专业、有人感的视觉语言：少一点“AI 工具感”，多一点“可信工作室”。

### 1.1 已确认方向

2026-07-11 已确认：界面造型以 Investment Desk 为主，吸收 Briefing Room 对时间、进度、项目状态的克制组织方式。

重要约束：

- 提醒不是压力放大器，而是温和的回看线索。
- 避免使用“你已经 21 天没有更新项目信息了”这类制造焦虑的表述。
- 推荐使用“你在 3 周前关注的项目，有新进展吗？”这类更自然的投资工作语言。
- 时间、进度、项目状态可以可见，但不应被设计成警报式体验。

Phase 1 已开始执行：优先改造工作台首页、导航命名、顶部栏和基础视觉基调。

## 2. 调研依据

本规划基于以下输入：

- 当前 Aivestor 仓库调研：导航、首页、项目列表/详情、组织工作台、数据应用、知识库、SKILL、报告和安全上下文。
- 现有产品定位：Aivestor 面向一级股权投资专业人员，核心叙事是“以投资人为中心，AI 赋能投资人持续进化”。
- 相邻产品外部调研：
  - Affinity：私募资本 CRM、关系智能、活动捕捉、分析/报告、项目来源和投后支持。
  - Intapp DealCloud：交易与关系智能、零录入活动捕捉、可配置工作流、关系图谱、审计轨迹和数据增强。
  - PitchBook：私募市场数据中心，公司/投资人/交易/基金数据、工作流中心、集成和组合监控。
  - AlphaSense：研究工作流、带引用的可信 AI 回答和市场情报。
  - Carta：私募资本操作系统、组合/基金数据可视化、工作流连接、利益相关方报告和组合数据收集。
  - Juniper Square：基金运营、投资人关系、募资、投资人体验和 AI 辅助 CRM。

关键市场趋势：

- 专业投资软件正在从静态记录系统走向实时工作流。
- CRM、Deal Flow、研究和组合监控正在融合。
- AI 的真正价值不是单独的聊天入口，而是嵌入具体工作流程。
- 专业用户信任来自可追溯来源、权限边界、审计历史和用户可控的数据主权。
- 专业工具的“人感”来自清晰、克制、有帮助的默认状态和恰当时机的提醒，而不是装饰性插画。

## 3. 当前状态诊断

### 3.1 优势

- 核心叙事清晰：个人投资记忆与数据主权。
- 项目分析链路较深：BP/文档上传、图片识别、财务提取、报告生成、来源标注、Word/PPT 导出。
- 知识飞轮有差异化：个人知识层与机构知识层并存。
- 机构版已有角色、权限、共享档案、LP 报告、协会报告和数据应用。
- SKILL 广场让产品具备固定模板之外的扩展性。
- 安全边界已有基础：24 小时登录上限与高敏操作二次确认。

### 3.2 体验短板

- 首页更像入口页，而不是指挥台。
- 导航按模块组织，不是按投资工作流组织。
- 项目列表缺少强运营信号：阶段健康度、下一步动作、缺失资料、负责人、置信度、近期变化。
- 项目详情页能力很多，但用户需要自己判断下一步该做什么。
- “AI”作为功能可见，但还没有足够自然地嵌入工作过程。
- 组织工作流已经存在，但还不像团队的日常作业节奏。
- 视觉系统干净但偏简陋：白底、少量卡片、层级有限、产品线索少、情绪温度不足。

### 3.3 不改造的产品风险

即使后端能力已经较复杂，用户仍可能把产品感知为内部工具或原型。这会削弱专业用户的信任，尤其是投资人通常期待系统能体现流程纪律、保密边界和高上下文工作能力。

## 4. 目标用户

### 4.1 核心用户画像

投资经理 / 分析师：

- 每周筛选大量早期项目。
- 需要快速初筛、结构化证据、可比较笔记和报告草稿。
- 痛点：BP 文件分散、AI 提示词反复写、历史判断难复用。

合伙人 / 决策者：

- 审阅项目更少，但单个项目风险更高。
- 需要 IC 可用摘要、分歧可见、关键假设和下行风险。
- 痛点：原始材料太多，真正决策信息不够集中。

投后负责人：

- 跟踪已投公司、更新、风险、指标、待办和对外汇报。
- 痛点：投后信息散落在文件、微信/邮件、路演材料和表格里。

机构管理员 / 运营合伙人：

- 管理团队知识、权限、组织资源、报告和产品使用。
- 痛点：知识留在个人手里，对外报告依赖人工拼接。

### 4.2 次级用户画像

LP / 外部利益相关方：

- 接收筛选后的报告、组合更新和基金/公司背景。
- 需要清晰、可信、一致的输出。

创始人 / 外部交易对象：

- 未来可能提交材料或回答尽调问题。
- 需要低摩擦的信息交换和清晰权限边界。

## 5. 核心工作任务

当我收到一个新项目时，我希望 Aivestor 能基于材料自动创建结构化项目工作区，帮助我判断是否值得继续投入时间。

当我重新打开一个项目时，我希望马上知道发生了什么变化、还缺什么、下一步该做什么，而不是重新靠记忆进入状态。

当我准备投委会时，我希望系统自动整理证据、团队观点、关键假设、风险和未解决问题，让会议从真实决策点开始。

当我讨论某家公司或赛道时，我希望相关历史判断和市场上下文自动出现，让过往经验可以被当前工作调用。

当投后公司发送更新时，我希望系统能提取指标、识别变化、提示风险并准备对外摘要，而不是让我手动拼接报告。

当团队共同使用平台时，我希望个人判断和机构知识既能分层保留，又能在需要时互相调用，避免协作抹平个人思考。

## 6. 界面方向选项

目标是在不把 Aivestor 做成消费类社交 App 或未来感 AI Demo 的前提下，增加产品温度、成熟感和可信度。

### 方案 A：Investment Desk，投资人工作台

定位：

- 一个安静、专业的工作台，像私募市场版的 Bloomberg / Notion / Linear。
- 适合：个人投资人、小团队、早期机构版。

视觉语言：

- 温暖的米白/纸面背景，深墨色文字，低饱和绿/蓝作为主强调色，琥珀色用于提醒。
- 信息密度更高，但保持可读。
- 保留左侧导航，但首页变成真正的工作台：今日工作、活跃项目、笔记、提醒。
- 卡片更扁平、更内容导向，减少大块空白。

人感来源：

- 文案使用投资工作语言，例如“今天需要你看的 3 件事”“这个项目缺少收入拆分”“上次判断距今 42 天”。
- AI 不作为冰冷助手面板出现，而是以“已整理好 / 建议下一步 / 仍缺少证据”的方式嵌入工作。

适用判断：

- 如果希望 Aivestor 显得可信、实用，并贴近投资人日常工作，应优先选择此方案。

### 方案 B：Partner Briefing Room，合伙人简报室

定位：

- 更偏管理层、会议室、决策优先。
- 适合：合伙人、投委会、机构版。

视觉语言：

- 深色顶部或侧边栏，白色内容区，强调文档和报告排版。
- 更大的状态面板：项目管线、IC 队列、投后提醒、LP 输出。
- 更多表格和 Memo 结构，减少活泼动效。

人感来源：

- 像进入一个已经准备好的会议室。
- 优先呈现“决策结论、分歧、证据、下一步”，而不是功能浏览。

适用判断：

- 如果 Aivestor 近期优先服务机构付费用户，可强化此方向。

### 方案 C：Research Journal，投资研究日志

定位：

- 带 AI 记忆的个人投资思考笔记。
- 适合：独立投资人、分析师、开源/社区叙事。

视觉语言：

- 更偏编辑器和笔记产品，温暖纸面感，更好的长文排版，突出每日记录、保存的想法和项目记忆。
- 项目与知识通过时间线和写作体验连接。

人感来源：

- 最能体现个人成长感。
- 最贴近“投资人持续进化”的品牌表达。

风险：

- 如果做得太强，可能弱化企业级可信度。

### 方案 D：Deal OS，交易操作系统

定位：

- 更标准的 SaaS 操作系统，围绕管线、任务、关系和分析构建。
- 适合：较大团队、可重复机构流程。

视觉语言：

- 更密集的表格、管线看板、右侧详情抽屉、筛选器、保存视图和任务标签。
- 更接近标准 B2B SaaS：负责人、状态、截止日期、优先级、工作流规则。

人感来源：

- 通过责任清晰和下一步动作设计体现人感。

风险：

- 如果过度靠近通用 CRM，会稀释 Aivestor “个人判断记忆”的差异化。

### 推荐风格选择

建议以方案 A 为基础，吸收方案 B 的两个要素：

- 方案 A 带来需要的产品温度和日常使用亲近感。
- 方案 B 保证面向机构用户的专业可信度。

工作命名：Investment Desk + Briefing Room，即“投资人工作台 + 决策简报室”。

实施原则：

- 默认界面：有人感、行动导向。
- 详情、会议、报告界面：严谨、决策导向。

## 8. 功能需求

### 8.1 投资人工作台

目标：

- 用每日工作面板替代当前简单首页。

核心模块：

- 今日关注：停滞项目、新解析材料、待回答问题、即将到来的会议、未完成报告。
- 活跃项目条：按紧急程度展示前 5 个活跃项目。
- 工作队列：下一步、负责人、截止日期、状态。
- 最近记忆：最新判断、已晋升知识、对话摘要。
- 快捷动作：新建项目、上传文档、询问研究问题、准备 IC Memo。

MVP 字段：

- `next_action`
- `next_action_due_at`
- `owner_user_id`
- `attention_reason`
- `last_meaningful_activity_at`

AI 辅助：

- 根据项目阶段和缺失证据生成下一步建议。
- 总结“你上次访问之后发生了什么变化”。
- 基于当前沉睡项目逻辑叠加阶段阈值，标记停滞项目。

### 8.2 项目管线

目标：

- 让投资生命周期可见、可管理。

建议阶段：

- 入库
- 初筛
- 首次会议
- 深度尽调
- IC 准备
- 条款谈判
- 已投
- 投后监控
- Pass
- 已退出

视图：

- 表格视图：用于严肃工作和筛选。
- 看板视图：用于阶段扫描。
- 保存筛选：按阶段、赛道、负责人、结果、缺失证据筛选。

MVP 要求：

- 将现有 `status`、`stage`、`process_stage` 和 `outcome` 梳理为用户可理解的生命周期模型。
- 迁移期间保持后端兼容。
- 增加项目健康标签：
  - 推进中
  - 等待创始人
  - 缺少证据
  - 可进入 IC
  - 已停滞
  - 高风险

### 8.3 项目工作区

目标：

- 让每个项目像一个持续演进的 Dossier，而不是一次性报告页。

推荐布局：

- 头部：公司、赛道、阶段、负责人、置信度、下一步。
- 主区域：决策摘要和关键材料。
- 右侧栏：AI 笔记、缺失证据、团队观点、近期活动。
- 时间线：材料、会议、判断、报告、决策、跟进。

必要区块：

- 概览：一页式项目简报。
- 材料：BP、财务模型、Deck、法律文件、更新文件。
- 分析：报告、财务图表、市场/竞争格局、带来源结论。
- 决策：多空理由、关键假设、红旗、置信度、合伙人分歧。
- 关系：创始人/联系人历史、介绍来源、会议历史。
- 投后：指标、更新、风险、行动项。
- 输出：IC Memo、LP 快照、Term Sheet、导出历史。

AI 辅助：

- “准备项目简报”
- “找出缺失的尽调问题”
- “与历史相似判断做对比”
- “基于当前证据生成 IC Memo”
- “提取投后更新指标”

### 8.4 轻量关系层

目标：

- 增加关系上下文，但 2.0 MVP 不做完整企业级 CRM。

实体：

- 人
- 机构
- 关系事件
- 介绍来源
- 会议
- 邮件/手工备注占位

MVP 要求：

- 将人和机构关联到项目。
- 记录介绍来源和会议笔记。
- 在组织层展示“谁认识谁”。
- 先支持手动关系强度评分。
- 后续在用户明确授权后再考虑邮件/日历捕捉。

为什么重要：

- 一级市场项目来源高度依赖关系网络。
- 同类产品普遍强调关系智能和自动活动捕捉。
- Aivestor 的差异化应是把关系上下文连接到投资判断，而不是只做联系人管理。

### 8.5 研究与知识

目标：

- 让知识出现在工作流里，而不是只存在于单独的知识库页面。

需求：

- AI 回答必须能引用上传文档、报告、知识和市场数据。
- 赛道/市场笔记：用户维护可投资观点和开放问题。
- 知识晋升流程保持显式。
- 报告定稿或强判断产生后，建议沉淀知识条目。
- 对注入知识提供“为什么看到这条”的说明。

MVP 升级：

- 在项目工作区内展示相关知识卡片。
- 统一置信度和来源提示。
- 增加“保存到投资论点”和“与历史案例对比”。

### 8.6 IC 准备

目标：

- 将分散分析整理为可开会的决策包。

需求：

- IC 议程生成。
- 项目一页纸。
- 决策 Memo。
- 团队判断对比。
- 开放问题与未解决风险。
- 证据完整度清单。
- 导出 Word/PPT。

MVP：

- 先在项目详情页增加一个“准备 IC Memo”动作。
- 复用现有报告、判断、文档、财务、评论和知识注入。
- 增加 IC 状态：草稿 / 已准备 / 已评审 / 已记录决策。

### 8.7 投后监控

目标：

- 从投前分析延伸到持续持有管理。

需求：

- 投后公司档案。
- 周期性更新上传。
- 指标提取和趋势图。
- 风险/事件流。
- 跟进行动列表。
- LP 可用快照。

MVP：

- 复用现有 `PostInvestment` 和档案能力。
- 给每家公司增加更新频率和指标结构。
- 先支持月度/季度更新手工上传，再考虑自动收集。

### 8.8 对外报告

目标：

- 通过可重复输出体现机构价值。

需求：

- LP 报告模板。
- 协会/监管底稿模板。
- 投后公司一页纸。
- IC Memo 归档。
- 导出历史和来源追踪。

MVP：

- 优化当前 LP/协会报告页面，增加模板预设和评审状态。
- 显示“来源完整度”和“最近更新”。

### 8.9 数据应用 2.0

目标：

- 将数据应用从孤立工具嵌入项目和研究工作流。

需求：

- 市场洞察卡片可挂载到项目。
- 机构点查结果可保存为关系/机构记录。
- 竞争格局 SKILL 可将结构化竞品写入项目工作区。

MVP：

- 增加“挂载到项目”动作。
- 保存数据来源引用。
- 展示数据新鲜度和来源免责声明。

### 8.10 信任、权限与审计

需求：

- 保留当前个人/组织知识分层。
- 保留高敏操作二次确认。
- 增加导出、组织共享、项目转入组织、知识晋升等动作的可见审计轨迹。
- 支持分析师、合伙人、管理员的角色化视图。
- AI 生成内容默认展示来源和置信度。

## 9. 非功能需求

易用性：

- 新用户应在 5 分钟内理解主工作流。
- 老用户应在 10 秒内看到当前优先事项。
- 项目负责人无需打开所有 Tab，也能理解项目状态。

性能：

- 工作台和项目管线应快速加载，AI 建议异步增强。
- AI 建议不能阻塞页面使用。

可靠性：

- 解析、提取和报告生成状态必须可见。
- 失败信息要能指导用户下一步操作。

隐私：

- 关系、日历、邮件捕捉必须由用户显式授权。
- 个人判断不得静默晋升为组织知识。

可访问性：

- 财务和状态数据要有足够对比度。
- 表格和筛选器支持键盘操作。
- 状态不能只依赖颜色表达。

## 10. 发布计划

### Phase 0：风格选择

交付物：

- 从上述方案中选择一个视觉方向。
- 制作 2-3 个目标页面方案：
  - 工作台
  - 项目工作区
  - 项目管线或 IC Memo

### Phase 1：体验外壳

交付物：

- 设计 Token：颜色、字体、间距、卡片/表格/按钮状态。
- 更新 App Shell：导航、顶栏、响应式结构。
- 工作台 v1。
- 项目列表/管线视觉升级。

成功标准：

- 产品立刻显得更成熟、更有人感。
- 不需要进行大规模数据模型迁移。

### Phase 2：项目工作区升级

交付物：

- 带生命周期状态和下一步动作的项目头部。
- 证据与缺失问题侧栏。
- 统一活动时间线。
- 改进文档、报告、决策流程。

成功标准：

- 用户始终知道项目状态和下一步动作。

### Phase 2.1：项目详情信息架构与投后入口收尾

触发原因：

- 上线后的项目详情页同时出现“下一步与证据完整度”“初筛-尽调-投委会-投后管理”“项目动态”三层信息，但三者分工不够清楚。
- 投后管理在股权投资工作里耗时最长，事务最多，退出策略对最终收益影响大，不能只作为流程末端状态。
- 设置页把投资人画像和系统设置混在一起，专业感不足。

交付物：

- 将项目详情重组为三层：项目当前状态、投资流程、项目记录。
- 将“下一步与证据完整度”改为“项目当前状态”，承载当前阶段、投资结果、当前动作、目标日期和证据完整度。
- 将“初筛-尽调-投委会-投后管理”明确为投资生命周期视图，阶段变化保留判断记录。
- 将“项目动态”改为“项目记录”，作为材料、判断、报告、会议和跟踪记录的时间线。
- 投后页签常驻为“投后规划/投后管理”，增强投后管理总览、经营跟踪、重大事项、风险预警、退出策略、收益与退出视图。
- 设置页拆分为投资偏好、账户与安全、AI 与模型、数据与协议。
- 2026-07-12 复盘调整：设置必须拆成独立子页面，而不是单页内锚点定位；项目详情不再保留独立“投资流程”进度条，阶段和投资结果回收到“项目当前状态”中维护。
- 2026-07-12 二次收敛：项目详情顶部不再重复展示阶段、下一步和证据卡片；“项目当前状态”成为唯一的阶段、结果、下一步和证据完整度维护入口。

成功标准：

- 用户打开项目详情时，能先判断“项目现在是什么状态”，再进入“完整流程到了哪里”，最后回看“历史记录和依据”。
- 未进入投后阶段的项目也可以提前维护投后规划和退出判断。
- 设置页中投资判断偏好和账号/模型/数据设置边界清楚。

### Phase 3：投资工作流升级

交付物：

- IC Memo 工作流。
- 团队判断对比升级。
- 关系记录 MVP。
- 项目内研究/知识卡片。

成功标准：

- Aivestor 可以支持一次真实投委会准备流程。

### Phase 4：投后与报告升级

交付物：

- 投后监控工作区。
- 指标更新提取。
- LP 快照/报告模板。
- 报告评审状态和导出历史。

成功标准：

- Aivestor 同时覆盖投前和投后工作。

### Phase 4.1：投后监控工作区 v1

落地边界：

- 先复用既有投后更新和会议记录，不新增数据库表。
- 将投后页从“记录入口”升级为“监控视图”，覆盖经营指标、重大事项、风险信号、退出与融资。
- 从投后更新文本中提取带数值的经营信号，形成轻量指标监控列表。
- 整理 LP 快照素材，为后续 LP 报告模板和导出历史打基础。
- 增强投后更新录入提示，让用户按经营、风险、融资、人员、退出等场景记录必要信息。

后续扩展：

- 指标字段结构化、趋势图和同环比。
- 投后行动项与负责人。
- 退出收益测算和多路径比较。
- LP 快照生成、评审状态和导出历史。

### Phase 4.2：投后材料收集与输出口径修正

触发原因：

- 投后管理的实际工作不只是手动填写更新，还包括收取和分析被投企业定期报告、财务报告、审计报告、经营报告，以及董事会、股东会等治理会议材料。
- “LP 快照素材”口径过窄，投后输出对象也包括内部分析、基金业协会报送、项目复盘和其他管理材料。

交付物：

- 增加投后材料文档分类：财务报告、审计报告、经营报告、董事会材料、股东会材料。
- 在投后管理页新增“报告与会议材料”上传区，复用现有项目文档上传、解析和材料库能力。
- 展示近期投后材料列表，区分定期报告和治理会议材料。
- 将“LP 快照素材”调整为“投后报告素材”，覆盖内部分析、协会报送和 LP 报告三类输出场景。

### Phase 4.3：项目详情首屏压缩与横向时间轴

触发原因：

- 项目详情顶部的标题、项目状态和纵向项目记录占位过高，用户打开项目后需要滚动才能进入项目分析、投资决策和投后规划。
- “项目当前状态”和“投资决策”中的投资节点控制存在阶段信息重复。
- 纵向项目记录会随着记录增加继续拉长，不适合作为首屏默认展示。

交付物：

- 移除项目详情顶部独立“项目当前状态”大卡片。
- 在项目标题右侧恢复阶段关键词，并在标题区用一行轻量摘要展示下一步、证据完整度和记录数量。
- 将项目记录改为横向时间轴，默认压缩高度，随记录和时间向右扩展。
- 将项目分析、投资决策、投后规划页签上移，使主工作流程在首屏可见。
- 阶段控制以“投资决策”中的投资节点控制为准，项目顶部只做状态摘要展示。
- 2026-07-13 复盘修正：横向时间轴应将最新记录放在最左侧；右侧栏删除与顶部摘要和项目记录重复的“当前动作”和“近期记录”卡片，只保留判断依据、投委会准备等辅助信息。
- 2026-07-13 进一步收敛：项目详情采用单一主工作区，删除右侧“判断依据”和“投委会准备”栏，避免与项目材料、投资决策重复；标题下仅保留下一步、材料解析、报告状态和记录数量等轻量摘要，项目分析、投资决策、投后规划三条主流程使用全宽布局。

### Phase 4.4：投后行动与退出策略基础能力

交付物：

- 投后行动项独立记录，支持负责人、截止日期、说明和状态维护。
- 退出策略独立记录，支持主要路径、备选路径、目标窗口、估值判断、回报判断和策略状态。
- 投后页从自由文本记录扩展为可持续维护的管理工作区。

实施边界：

- 行动项和退出策略与项目权限范围保持一致，个人项目和组织项目均复用现有访问控制。
- 指标趋势、报告模板和导出历史另行推进，避免把多个输出流程混在一次数据迁移中。

### Phase 4.5：结构化投后指标

交付物：

- 在文本识别线索之外，增加用户确认后的指标记录入口。
- 支持指标名称、数值、单位、周期和口径说明。
- 为后续趋势、同环比和投后报告输出保留结构化数据基础。

### Phase 4.6：投后报告输出闭环

交付物：

- 基于当前投后更新、结构化指标、行动项和退出策略生成项目级投后报告底稿。
- 支持内部投后复盘、LP 投后更新和协会报送底稿三种模板口径。
- 支持草稿、评审中、已通过和已归档状态。
- 复用现有 Word 导出能力，并记录投后报告导出历史。

## 11. MVP 范围建议

近期最值得优先实现的是：

1. 采用“投资人工作台 + 决策简报室”的视觉系统刷新。
2. 用工作台替代当前基础 Dashboard。
3. 将项目列表升级为项目管线/工作队列。
4. 在项目详情中增加项目头部和右侧“下一步 / 缺失证据 / 近期活动”侧栏。
5. 增加 IC Memo 生成入口，复用现有报告、判断、评论、文档和财务数据。
6. 将知识卡片嵌入项目详情。

暂不建议优先做：

- 完整邮件/日历活动捕捉。
- 完整 CRM 替代。
- 复杂自定义工作流引擎。
- 在核心工作台改造前做重型图表/分析大改。

## 12. UI 文案方向

语气：

- 冷静、具体、专业。
- 避免过度使用“AI 驱动”“智能体”“颠覆”等词。
- 优先使用投资工作语言。

示例：

- “今天需要你处理”
- “这个项目还缺 3 类证据”
- “上次判断后新增了 2 份材料”
- “可进入 IC 准备”
- “建议先补充收入拆分和客户集中度”
- “这些结论来自 BP、财务模型和你的历史判断”
- “团队意见存在分歧”
- “已沉淀为机构知识副本，个人原始记录保留”
