# Aivestor 桌面与移动界面 Demo 融合实施计划

> 日期：2026-11-13  
> 输入：中鉴智投桌面版 `aivestor-demo.html`、移动版 `aivestor-mobile.html`、Aivestor 2.0 既有规划与当前主线代码。  
> 产品边界：作为 Aivestor 共用响应式能力实施，不建立中鉴专用前端分叉，不改变深度投研、报告、权限和数据模型。

## 1. 结论

两份 Demo 与既有“工作台—项目管线—项目工作区”改造方向总体一致，可以融合。它们最有价值的不是具体颜色或静态示例，而是三条体验原则：

1. 用户从明确的工作目标进入系统，而不是先理解功能模块。
2. 项目材料、分析结论、缺口和后续推进在同一个连续项目空间内呈现。
3. 移动端保留高频查看和推进能力，不复制桌面端全部密度。

实施采用同一套 Next.js 路由、权限和数据，桌面与移动共享组件，只在布局和信息密度上响应式变化。

## 2. 与现有规划的关系

| Demo 诉求 | 现有 Aivestor 方向 | 融合决策 |
|---|---|---|
| 桌面首页以一句话/场景开始工作 | 已有“今日优先事项”和六类工作场景 | 保留今日优先事项；增加真实可跳转的高频工作入口。自由文本总入口待任务路由具备后再做，不放置无效输入框 |
| 项目卡片与项目档案 | 已有项目管线和独立档案 | 活跃项目继续进项目管线；历史与投后继续进档案，不把两种语义合并 |
| 原版 BP—分析报告—投后跟踪 | 已有项目分析—投资决策—投后管理三阶段 | 保留业务阶段；在阶段内部强化材料、报告、追踪的移动阅读层级，不替换现有报告类型 |
| 移动端底部四入口 | 现有移动抽屉已覆盖全部功能 | 增加四个高频底部入口；抽屉继续承载完整导航 |
| 桌面版和手机版两个 Demo | 当前产品为响应式 Web | 做一个响应式产品，不维护两套代码、两套数据或独立移动 App |

不存在架构冲突。需要控制的主要风险是：Demo 中的静态数字、模型选择、语音、上传和来源抽屉不能被直接复制为不可用控件。

## 3. 分期与优先级

### P0：共用外壳与真实入口（已启动）

- 提取桌面/移动共享导航定义。
- 移动端增加“工作台、项目、情报、我的”四个高频底部入口，完整功能仍从侧栏进入。
- 工作台增加三个真实高频入口：单项目分析、批量初筛、行业研究；其余场景继续渐进展开。
- 不增加数据库迁移，不改 API，不改变白标、权限和报告类型。

预计 AI 主导开发与回归：0.5—1 个工作日。

### P1：项目管线与项目工作区响应式收口（已完成）

- 项目管线移动端改为紧凑卡片，突出项目、阶段、结论、最近更新和下一步。
- 筛选在窄屏收成可展开面板，但搜索和“重点项目”保持直接可达。
- 项目工作区移动端固定三阶段导航，压缩项目头部；材料、报告、证据和跟踪分别使用可折叠区块。
- 桌面端继续保留今日优先事项和宽屏证据布局，不照搬手机卡片。

预计 AI 主导开发与回归：1—2 个工作日。

完成记录（2026-11-13）：

- 移动项目列表使用紧凑卡片，直接呈现阶段、结论、报告状态、最近更新和真实下一步。
- 搜索与重点项目保持常驻；融资阶段、流程阶段、投资结论、分类、标签和排序在窄屏收进可展开筛选面板。
- 项目头部在移动端压缩；三阶段导航使用可访问 tab 语义，并在移动长页面滚动时吸顶。
- 材料与证据、关系与知识、材料原文、分析与报告在窄屏渐进展开；1440px 桌面端继续使用宽屏证据和双栏布局。
- 390、768、1024、1440 四档浏览器验证通过，筛选展开、阶段切换和长页面吸顶通过；最新 `design-qa.md` 为 `final result: passed`。
- 本期没有数据库迁移、API 变更、客户专属分叉或静态演示控件。

### P2：统一任务入口与移动操作闭环（已完成）

- 在确认真实任务路由后，增加一句话任务入口：识别目标并进入新项目、批量初筛、行业研究、尽调准备、IC 或情报流程。
- 输入内容必须能带入目标页面或创建可追踪任务；在此前不放置“看起来能用、实际丢失输入”的输入框。
- 补移动上传、运行状态、失败恢复和来源抽屉；复用既有上传、Worker 和证据定位能力。

预计 AI 主导开发与回归：1—2 个工作日。

完成记录（2026-11-13）：

- 工作台新增一句话任务入口，使用确定性规则识别项目分析、批量初筛、行业研究、尽调准备、投资决策和持续情报六类目标；用户可在提交前手动切换类型。
- 项目分析任务说明写入既有 `projects.next_action/workspace_note`；批量初筛写入批次筛选条件；行业研究和尽调说明预填到 SKILL 运行面板；情报说明预填到主题创建流程；IC 说明随项目选择进入投资决策工作区，可一键保存为项目下一步。
- 新增移动来源抽屉，集中回看原始文件、解析状态和材料文本；没有复制或另存项目材料。
- 复用既有 `FileUploader` 和深度投研 Worker 状态：上传失败可重试且重试完成后正确刷新项目；后台研究状态、失败原因和重试入口在移动端具备 44px 触控目标和可访问状态提示。
- 本期不新增数据库表或迁移，不建立通用空壳任务队列；仅扩展项目创建接口以写入已经存在的工作流字段。
- 任务识别、项目工作流、批量初筛、主线 UX、TypeScript 和生产构建完成回归；浏览器验证任务识别、IC 输入传递、来源抽屉和控制台状态，最新 `design-qa.md` 为 `final result: passed`。

### 上线前验收

- 390、768、1024、1440 px 四档响应式检查。
- 键盘焦点、200% 缩放、触控目标、底部安全区和屏幕阅读顺序检查。
- Aivestor 与中鉴白标分别完成导航、项目、报告、深度投研和情报回归。
- 无数据库迁移时先灰度界面；生产发布继续使用不可变 Release 和现有回滚流程。

预计工程验收与发布准备：0.5 个工作日。全量 P0—P2 合计约 3—5 个 AI 协作工作日，取决于统一任务入口是否需要新增服务端任务编排。

## 4. 本轮明确不做

- 不建立原生移动 App 或中鉴专用代码分支。
- 不用 Demo 的静态案例替换真实项目数据。
- 不合并项目管线与历史档案的数据语义。
- 不重做深度投研、报告导出或情报研究引擎。
- 不实现只有单一客户临时需要、无法被主线复用的界面控件。

## 5. 验收指标

- 移动端从任意主页面一次点击可到工作台、项目、情报和个人设置。
- 用户在工作台 5 秒内能找到新项目、批量初筛或行业研究入口。
- 现有页面、API、报告 kind、权限和白标边界不变。
- 所有新增入口都指向真实可用流程，不存在仅演示的按钮或输入框。
- 桌面和移动共享路由与组件，避免后续双倍维护成本。
